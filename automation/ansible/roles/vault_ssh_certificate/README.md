# vault_ssh_certificate

Configures Vault's SSH secrets engine as the homelab SSH **client (user) CA**. Idempotent —
re-running does not rotate the CA key or disturb already-issued certificates.

Requires `VAULT_TOKEN` exported in the operator's shell (never read from a file, never
committed). Talks to Vault via `kubectl exec` into the running Vault pod, so it works
whether or not Vault is exposed outside the cluster.

Configures:
- `ssh-client-signer` — SSH secrets engine mount, CA key generated by Vault (private key
  never leaves Vault)
- Signing role `homelab-ansible` — `allowed_users=ansible`, `default_extensions=permit-pty`
  only (no agent/X11/TCP forwarding), `ttl=30m`, `max_ttl=60m`
- Vault policy `homelab-ansible-sign` — `update` only on `ssh-client-signer/sign/homelab-ansible`
  and `ssh-client-signer/issue/homelab-ansible` (the minimum required to issue certificates
  through this one role)
- Kubernetes auth role `semaphore-ansible` — bound to ServiceAccount `semaphore-ansible` in
  namespace `semaphoreui` only, mapped to the `homelab-ansible-sign` policy

Exposes `vault_ssh_ca_public_key` as a fact for `roles/ssh_automation_account` to install on
nodes as `TrustedUserCAKeys`. Only the CA **public** key is ever handled outside Vault.

Run via `scripts/lifecycle/bootstrap-control-tower.sh vault-ca` (Wave -1c live activation
only — never in the repo-only pass).
