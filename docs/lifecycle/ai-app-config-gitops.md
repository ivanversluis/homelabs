# OpenClaw and Open WebUI configuration as GitOps

## Desired authority model

Configuration has three explicit owners:

- **Git** owns non-secret application configuration and topology.
- **Vault** owns credentials and sensitive deployment-specific values.
- **PVCs** own mutable application state only.

GUI/CLI configuration is not authoritative. A pod restart must reconstruct the same effective configuration from Git + Vault.

## OpenClaw

OpenClaw now separates configuration from state:

- `OPENCLAW_CONFIG_PATH=/runtime/openclaw/openclaw.json`
- `OPENCLAW_STATE_DIR=/home/node/.openclaw`
- Git owns `openclaw-runtime-config.yaml`.
- The init container renders the regular config file into an `emptyDir` from the Git template plus Vault-backed environment values.
- The main container mounts the rendered config read-only.
- No `openclaw config set` or `openclaw models set` commands are used during startup.
- The PVC is only mutable state (sessions, workspace, memory, credentials/runtime state).

The existing `openclaw-config` ConfigMap is retained for `AGENTS.md` and `k8s-monitor.js`; its historical `openclaw.json` key is removed from the rendered object by Kustomize.

## Open WebUI

Open WebUI uses:

```text
ENABLE_PERSISTENT_CONFIG=false
```

This makes Kubernetes environment variables authoritative for ConfigVar-backed settings. The PVC/database remains for users, conversations, history, and other application state.

Git defines:

- Kong OpenAI-compatible endpoint
- Ollama disabled
- Authentik/OIDC wiring
- direct-tool-server enablement
- Kubernetes and Nmap MCPO topology

Vault provides:

- Kong AI Gateway client key
- MCP consumer key
- OIDC client secret and related sensitive values

`TOOL_SERVER_CONNECTIONS` is generated by External Secrets so the MCP bearer key is never committed to Git.

## Clean restart without deleting PVCs

This is the preferred first validation. It proves configuration is reconstructed without destroying state:

```bash
kubectl -n openclaw rollout restart deployment/openclaw
kubectl -n ai rollout restart deployment/openwebui

kubectl -n openclaw rollout status deployment/openclaw --timeout=180s
kubectl -n ai rollout status deployment/openwebui --timeout=300s
```

Verify OpenClaw config path and state path:

```bash
POD=$(kubectl -n openclaw get pod -l app.kubernetes.io/name=openclaw -o jsonpath='{.items[0].metadata.name}')
kubectl -n openclaw exec "$POD" -- sh -c 'printf "config=%s\nstate=%s\n" "$OPENCLAW_CONFIG_PATH" "$OPENCLAW_STATE_DIR"'
```

Expected:

```text
config=/runtime/openclaw/openclaw.json
state=/home/node/.openclaw
```

Validate the active OpenClaw configuration without printing secrets:

```bash
kubectl -n openclaw exec "$POD" -- node /app/dist/index.js config get agents.defaults.model
kubectl -n openclaw exec "$POD" -- node /app/dist/index.js config get models.providers.kong.baseUrl
```

Expected model:

```text
kong/claude-sonnet-4-6
```

Verify Open WebUI environment authority without printing keys:

```bash
POD=$(kubectl -n ai get pod -l app.kubernetes.io/name=openwebui -o jsonpath='{.items[0].metadata.name}')
kubectl -n ai exec "$POD" -- sh -c 'printf "persistent=%s\nbase=%s\n" "$ENABLE_PERSISTENT_CONFIG" "$OPENAI_API_BASE_URL"'
```

Expected:

```text
persistent=false
base=https://llm-gw.<domain>/v1
```

## Full application-state reset (destructive)

Only use this when you intentionally want to discard the existing application state and prove a clean bootstrap.

### Safety check

First inspect PVC/PV identity and reclaim policy:

```bash
kubectl -n openclaw get pvc openclaw-data -o wide
kubectl -n ai get pvc openwebui-data -o wide

kubectl get pv "$(kubectl -n openclaw get pvc openclaw-data -o jsonpath='{.spec.volumeName}')" -o custom-columns=NAME:.metadata.name,RECLAIM:.spec.persistentVolumeReclaimPolicy,SC:.spec.storageClassName
kubectl get pv "$(kubectl -n ai get pvc openwebui-data -o jsonpath='{.spec.volumeName}')" -o custom-columns=NAME:.metadata.name,RECLAIM:.spec.persistentVolumeReclaimPolicy,SC:.spec.storageClassName
```

If there is data you may need later, create/verify a Longhorn snapshot or backup first.

### Stop the workloads

Suspend Flux reconciliation temporarily so it does not recreate workloads/PVCs while state is being reset:

```bash
flux suspend kustomization openclaw -n flux-system
flux suspend kustomization ai -n flux-system

kubectl -n openclaw scale deployment/openclaw --replicas=0
kubectl -n ai scale deployment/openwebui --replicas=0
```

Wait until pods are gone:

```bash
kubectl -n openclaw wait --for=delete pod -l app.kubernetes.io/name=openclaw --timeout=120s || true
kubectl -n ai wait --for=delete pod -l app.kubernetes.io/name=openwebui --timeout=120s || true
```

### Delete only the claims

```bash
kubectl -n openclaw delete pvc openclaw-data
kubectl -n ai delete pvc openwebui-data
```

Do **not** manually clear PV `claimRef`, delete Longhorn volumes, or patch reclaim policies as part of a normal reset. The Git manifests still declare the PVCs, so Flux will create fresh claims when reconciliation resumes.

### Resume GitOps

```bash
flux resume kustomization openclaw -n flux-system
flux resume kustomization ai -n flux-system

flux reconcile kustomization openclaw -n flux-system --with-source
flux reconcile kustomization ai -n flux-system --with-source

flux get kustomizations -n flux-system
```

Watch fresh claims and pods:

```bash
kubectl -n openclaw get pvc,pod -w
kubectl -n ai get pvc,pod -w
```

## What not to remove

Do not delete the PVC definitions from Git merely to obtain a clean restart. They are still required for application state:

```text
infra/openclaw/openclaw-pvc.yaml
workloads/apps/ai/openwebui/openwebui-pvc.yaml
```

A clean GitOps proof is that configuration comes back from Git/Vault regardless of whether the state PVC is retained or recreated.

## Acceptance criteria

1. OpenClaw starts with `kong/claude-sonnet-4-6` without any manual CLI configuration.
2. `OPENCLAW_CONFIG_PATH` points outside the state PVC and is mounted read-only in the main container.
3. Open WebUI starts with `ENABLE_PERSISTENT_CONFIG=false` and the Kong endpoint from Git.
4. Open WebUI tool connections appear without using the Admin UI.
5. Secrets are sourced from Vault/External Secrets and are not present in Git.
6. Restarting both Deployments does not change their effective configuration.
7. Recreating both PVCs does not require configuration through either GUI or CLI.
